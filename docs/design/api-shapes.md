## Traps

- `GET /api/tasks` returns a bare array without query parameters and `{tasks, total, limit, offset}` with any. Task `origin` is `approval`, `rerun` or `direct`; statuses include `pending`, `stalled` and `expired`, all derived by the server.
- `GET /api/incidents` accepts `state` only as a comma list of `pending`, `open`, `acknowledged`, `resolved` and answers 400 "unknown state" for anything else. `active`, `snoozed` and `all` are console URL filter names, never API values.
- `/api/audit` filters are `action`, `actor_id`, `at_from`, `at_to`, `correlation_id`, `decision`, `exclude_action`, `exclude_decision`, `node_id`, `scope`, `token_id`, `q`, `limit`, `offset`; there is no id filter.
- `/api/network/approvals` list filters are `status`, `plugin`, `node_id`, `since`, plus `limit`, `offset`, `include_dismissed`, `count`, `include=plan`; there is no `until`.
- Notify delivery filters are `channel_id`, `event_type`, `outcome`, `event_id`, `source`, `source_id`.
- Plan endpoints answer in five shapes: `{approval, findings}` (SSH Guard, DNS and similar plans), a bare `ApprovalView` (agent update), `{approval}`, `BeaconPlanResponse {approval, plan, findings}`, and `GroupPolicyPlanResult {affected, conflicts, orphaned, selector_impacts}`. `POST /api/netpolicy/convert` returns `NetPolicyConvertResult {group_policy, approval|null}`.
- `GET /api/sshguard/status` rows carry `stage`, a `posture` object, `revert_deadline` and `actionable_approval_id`; the read needs `sshguard:read` plus `network:plan` per node and skips the rest without a hidden count.
- `GET /api/monitors/paths` sends `degraded_at` (possibly null) only from a server that judges degraded, and `beacon_replans` with the request that would replan each drifted node.
